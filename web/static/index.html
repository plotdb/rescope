rescope

rescope loads third party JavaScript and runs it against a substituted global. Two versions of the same library can be live on one page without either of them knowing, and neither of them touches what the page itself has on window.

A scoped library is fetched, wrapped and evaluated rather than loaded as a <script>, so the interesting questions are about what it can still tell about its surroundings: whether it finds its own file in a stack trace, where it thinks it was loaded from, and what of the host page leaks in. Each section below answers one of those, in this browser, when you press its button.

Error line

A scoped library does not run as a file of its own, so the only thing keeping its stack traces honest is the //# sourceURL rescope appends. Each sample throws on purpose; the two panes are the same throw seen through rescope and through a plain <script src>.

Bundle round trip

bundle fetches a set of libraries once and records their export names with them. A page loading that bundle knows the names up front, so it never has to run a library a second time to find them out - and never creates the peek window.
